Part 3: Repository & 초기 데이터

이번 파트에서는 데이터베이스에 접근하는 Repository 인터페이스를 만들고, 테스트용 초기 데이터(data.sql)를 작성합니다.

Repository란?
Entity(테이블)에 대한 CRUD(생성·조회·수정·삭제) 작업을 담당하는 계층입니다.
Spring Data JPA의 JpaRepository를 상속(extends)하면 SQL을 한 줄도 작성하지 않고 기본 CRUD 메서드를 사용할 수 있습니다.

비유: "냉장고 정리 도우미" — "김치 꺼내줘", "우유 넣어줘" 라고 말만 하면 알아서 처리해주는 도우미입니다. 우리는 냉장고(DB) 안의 구조를 몰라도 됩니다!

Step 9. Repository 인터페이스 만들기 (5개)

각 Entity마다 하나의 Repository를 만듭니다. interface로 선언만 하면 Spring이 자동으로 구현체를 생성합니다.

JpaRepository가 기본 제공하는 메서드들
아래 메서드들은 코드에 안 보여도 자동으로 사용할 수 있습니다:
save(entity) — 저장(INSERT) 또는 수정(UPDATE)
findById(id) — ID로 1건 조회
findAll() — 전체 목록 조회
deleteById(id) — ID로 삭제
count() — 전체 개수

package com.example.mymatzip.repository; import com.example.mymatzip.entity.Member; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.data.domain.Page; import org.springframework.data.domain.Pageable; import java.util.Optional; public interface MemberRepository extends JpaRepository<Member, Long> { // 이메일로 회원 조회 (로그인 시 사용) // → SELECT * FROM member WHERE email = ? Optional<Member> findByEmail(String email); // 이메일 중복 확인 (회원가입 시 사용) // → SELECT COUNT(*) > 0 FROM member WHERE email = ? boolean existsByEmail(String email); // 닉네임 중복 확인 (회원가입 시 사용) // → SELECT COUNT(*) > 0 FROM member WHERE nickname = ? boolean existsByNickname(String nickname); // OAuth 소셜 로그인 회원 조회 // → SELECT * FROM member WHERE provider = ? AND provider_id = ? Optional<Member> findByProviderAndProviderId(String provider, String providerId); // 전체 회원 목록 페이징 조회 (관리자용) Page<Member> findAll(Pageable pageable); }
Query Method 규칙 — 메서드 이름이 곧 SQL!

Spring Data JPA는 메서드 이름을 분석해서 SQL을 자동 생성합니다:

findBy + 필드명 → WHERE 필드 = 값
existsBy + 필드명 → 존재하면 true, 없으면 false
findBy + 필드1 + And + 필드2 → WHERE 필드1 = ? AND 필드2 = ?

비유: 도서관 사서에게 "제목이 '자바'인 책 찾아주세요"라고 말하면 알아서 찾아주는 것과 같습니다.
Optional<T>이란?
"값이 있을 수도, 없을 수도 있는 안전 상자"입니다.
비유: 택배 상자를 열었을 때 물건이 있을 수도, 없을 수도 있는 것.
null 대신 Optional을 사용하면 NullPointerException을 방지할 수 있습니다.
.orElseThrow()로 값이 없을 때 에러를 던지거나, .orElse(기본값)으로 대체값을 설정할 수 있습니다.

package com.example.mymatzip.repository; import com.example.mymatzip.entity.Category; import com.example.mymatzip.entity.Restaurant; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.data.jpa.repository.EntityGraph; import org.springframework.data.jpa.repository.Query; import org.springframework.data.domain.Page; import org.springframework.data.domain.Pageable; import org.springframework.data.repository.query.Param; import java.util.List; public interface RestaurantRepository extends JpaRepository<Restaurant, Long> { // 카테고리별 맛집 목록 조회 @EntityGraph(attributePaths = {"member"}) List<Restaurant> findByCategory(Category category); // 카테고리별 맛집 목록 페이징 조회 @EntityGraph(attributePaths = {"member"}) Page<Restaurant> findByCategory(Category category, Pageable pageable); // 키워드로 맛집 검색 (이름 또는 주소에 포함) @EntityGraph(attributePaths = {"member"}) @Query("SELECT r FROM Restaurant r " + "WHERE LOWER(r.name) LIKE LOWER(CONCAT('%', :keyword, '%')) " + "OR LOWER(r.address) LIKE LOWER(CONCAT('%', :keyword, '%'))") List<Restaurant> searchByKeyword(@Param("keyword") String keyword); // 키워드 검색 + 페이징 @EntityGraph(attributePaths = {"member"}) @Query("SELECT r FROM Restaurant r " + "WHERE LOWER(r.name) LIKE LOWER(CONCAT('%', :keyword, '%')) " + "OR LOWER(r.address) LIKE LOWER(CONCAT('%', :keyword, '%'))") Page<Restaurant> searchByKeyword(@Param("keyword") String keyword, Pageable pageable); // 최신 등록순 상위 6개 맛집 조회 (메인 페이지용) @EntityGraph(attributePaths = {"member"}) List<Restaurant> findTop6ByOrderByCreatedAtDesc(); // 전체 맛집 목록 페이징 조회 @EntityGraph(attributePaths = {"member"}) Page<Restaurant> findAll(Pageable pageable); // 특정 회원이 등록한 맛집 목록 (마이페이지용) @EntityGraph(attributePaths = {"member"}) Page<Restaurant> findByMemberId(Long memberId, Pageable pageable); // 특정 회원이 등록한 맛집 수 (통계용) long countByMemberId(Long memberId); }
@EntityGraph란? — N+1 문제 해결사
맛집 10개를 조회할 때 등록자(member) 정보를 가져오기 위해 추가로 10번 DB를 조회하는 비효율적인 현상이 N+1 문제입니다.
@EntityGraph(attributePaths = {"member"})를 붙이면 맛집 + 등록자를 한 번의 JOIN 쿼리로 가져옵니다.

비유: 도서관에서 책을 빌릴 때, "저자 정보도 한꺼번에 가져와주세요"라고 사서에게 미리 말해두는 것입니다.
@Query와 JPQL이란?
메서드 이름 규칙으로 표현하기 어려운 복잡한 쿼리를 직접 작성하는 방법입니다.
JPQL은 SQL과 비슷하지만, 테이블 대신 Java 엔티티(클래스)를 기준으로 작성합니다.

LOWER(r.name) LIKE LOWER(CONCAT('%', :keyword, '%'))
→ 대소문자 무시하고, 이름에 키워드가 포함된 맛집을 찾아라

@Param("keyword")은 JPQL의 :keyword 자리에 실제 값을 넣어주는 연결 고리입니다.
비유: 메모지의 빈칸(:keyword)에 실제 값("돈까스")을 채워 넣는 것

package com.example.mymatzip.repository; import com.example.mymatzip.entity.Review; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.data.jpa.repository.Query; import org.springframework.data.repository.query.Param; import org.springframework.data.jpa.repository.EntityGraph; import org.springframework.data.domain.Page; import org.springframework.data.domain.Pageable; import java.util.List; public interface ReviewRepository extends JpaRepository<Review, Long> { // 특정 맛집의 리뷰 목록 조회 (최신순) @EntityGraph(attributePaths = {"member"}) List<Review> findByRestaurantIdOrderByCreatedAtDesc(Long restaurantId); // 특정 맛집의 평균 별점 계산 @Query("SELECT AVG(r.rating) FROM Review r WHERE r.restaurant.id = :restaurantId") Double averageRatingByRestaurantId(@Param("restaurantId") Long restaurantId); // 특정 회원이 작성한 리뷰 목록 List<Review> findByMemberId(Long memberId); // 맛집별 리뷰 페이징 조회 @EntityGraph(attributePaths = {"member"}) Page<Review> findByRestaurantId(Long restaurantId, Pageable pageable); // 특정 회원의 리뷰 페이징 조회 (마이페이지) @EntityGraph(attributePaths = {"member", "restaurant"}) Page<Review> findByMemberId(Long memberId, Pageable pageable); // 신고된 리뷰 목록 (관리자용) List<Review> findByReportedTrue(); // 특정 회원의 리뷰 수 (통계용) long countByMemberId(Long memberId); }
반환 타입이 Double(대문자)인 이유
averageRatingByRestaurantId()의 반환 타입이 double(소문자)이 아니라 Double(대문자)인 이유:
리뷰가 하나도 없으면 평균이 null인데, double은 null을 담을 수 없어 에러가 납니다.
Double(래퍼 클래스)은 null을 담을 수 있어 안전합니다.

비유: 시험 응시자가 0명이면 평균 점수는 "없음"이어야 합니다.

package com.example.mymatzip.repository; import com.example.mymatzip.entity.Reply; import org.springframework.data.jpa.repository.JpaRepository; import org.springframework.data.jpa.repository.EntityGraph; import java.util.List; public interface ReplyRepository extends JpaRepository<Reply, Long> { // 특정 리뷰의 대댓글 목록 조회 (오래된 순 — 대화 흐름 유지) @EntityGraph(attributePaths = {"member"}) List<Reply> findByReviewIdOrderByCreatedAtAsc(Long reviewId); // 특정 회원이 작성한 대댓글 목록 List<Reply> findByMemberId(Long memberId); }
Asc vs Desc 정렬 순서
리뷰는 Desc(내림차순 = 최신이 위)로 정렬하지만,
대댓글은 Asc(오름차순 = 오래된 것이 위)로 정렬합니다.
이유: 대화의 흐름을 자연스럽게 보여주기 위해서입니다 (카카오톡처럼).

Step 10. data.sql — 테스트용 초기 데이터

서버가 시작될 때 자동으로 실행되는 SQL 파일입니다. 매번 수동으로 데이터를 입력하지 않아도 테스트할 수 있습니다.

data.sql 실행 순서
1. JPA가 @Entity 기반으로 테이블을 생성 (CREATE TABLE)
2. spring.jpa.defer-datasource-initialization=true 설정으로 data.sql 실행 대기
3. spring.sql.init.mode=always 설정으로 data.sql의 INSERT문 자동 실행

비유: 새 가게를 열었을 때 진열대에 샘플 상품을 미리 진열해두는 것입니다.
