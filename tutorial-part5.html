Part 5: Utility & Service 계층

이번 파트에서는 보안 유틸리티(HtmlSanitizer)와 핵심 비즈니스 로직을 담당하는 Service 클래스 7개를 만듭니다.

Service 계층이란?
Controller(요청 접수) → Service(업무 처리) → Repository(DB 접근)

Service는 비즈니스 로직을 담당하는 핵심 계층입니다. 중복 확인, 권한 검증, 데이터 변환 등 "진짜 업무"가 여기서 이루어집니다.

비유: "은행 창구 직원" — 고객(Controller)이 "계좌 개설해주세요"라고 요청하면, 직원(Service)이 중복 확인 → 서류 작성 → 금고(Repository)에 저장합니다.

Step 13. HtmlSanitizer — XSS 공격 방어 유틸리티

사용자가 입력한 텍스트에서 악성 HTML/JavaScript 코드를 무력화하는 보안 유틸리티입니다.

XSS(Cross-Site Scripting) 공격이란?
악의적인 사용자가 입력란에 JavaScript 코드를 넣어서, 다른 사용자의 브라우저에서 실행되게 하는 공격입니다.

예시: 리뷰 내용에 <script>alert('해킹!')</script>를 입력
→ 다른 사용자가 이 리뷰를 보면 "해킹!" 팝업이 뜸
→ 더 나쁜 경우: 쿠키(세션 정보)를 훔쳐서 로그인 세션을 탈취할 수 있음!

비유: "식재료 농약 검사" — 음식(사용자 입력)을 손님(브라우저)에게 내기 전에 유해 물질(악성 스크립트)을 제거하는 소독 과정입니다.

package com.example.mymatzip.util; import org.springframework.web.util.HtmlUtils; public class HtmlSanitizer { // HTML 특수 문자를 이스케이프하여 XSS 공격을 방어 // 변환: < → &lt; > → &gt; " → &quot; & → &amp; ' → &#39; // // 입력: <script>alert('XSS')</script> // 출력: &lt;script&gt;alert(&#39;XSS&#39;)&lt;/script&gt; // → 브라우저에서 텍스트로 표시되지만 실행되지 않음! public static String sanitize(String input) { if (input == null) { return null; } return HtmlUtils.htmlEscape(input); } }

Service에서 사용자 입력을 DB에 저장하기 전에 반드시 호출합니다.

Step 14. MemberService — 회원 서비스

회원가입, 로그인, 회원 조회 등 회원과 관련된 핵심 업무를 처리합니다.

주요 개념 미리보기
@Service — 이 클래스가 비즈니스 로직 담당임을 Spring에 등록
@Transactional — DB 작업을 하나의 작업 단위로 묶음 (실패 시 전부 취소)
@RequiredArgsConstructor — final 필드에 대한 생성자를 Lombok이 자동 생성

비유: "은행 창구 직원" — 고객 신원 확인(로그인), 계좌 개설(회원가입), 정보 조회(findById)

package com.example.mymatzip.service; import com.example.mymatzip.dto.LoginForm; import com.example.mymatzip.dto.MemberSignupForm; import com.example.mymatzip.entity.Member; import com.example.mymatzip.entity.Role; import com.example.mymatzip.repository.MemberRepository; import lombok.RequiredArgsConstructor; import org.springframework.security.crypto.password.PasswordEncoder; import org.springframework.stereotype.Service; import org.springframework.transaction.annotation.Transactional; @Service // Spring에 서비스 클래스로 등록 @RequiredArgsConstructor // final 필드 생성자 자동 생성 → DI @Transactional(readOnly = true) // 기본: 읽기 전용 트랜잭션 (성능 최적화) public class MemberService { private final MemberRepository memberRepository; // 회원 DB 접근 private final PasswordEncoder passwordEncoder; // 비밀번호 암호화 도구 // ── 회원가입 ────────────────────────────────────────── @Transactional // 쓰기 작업 → readOnly 해제 public Member signup(MemberSignupForm form) { // [1단계] 이메일 중복 확인 if (memberRepository.existsByEmail(form.getEmail())) { throw new IllegalArgumentException("이미 사용 중인 이메일입니다."); } // [2단계] 닉네임 중복 확인 if (memberRepository.existsByNickname(form.getNickname())) { throw new IllegalArgumentException("이미 사용 중인 닉네임입니다."); } // [3단계] Member 객체 생성 + 비밀번호 BCrypt 암호화 Member member = Member.builder() .email(form.getEmail()) .password(passwordEncoder.encode(form.getPassword())) // 암호화! .nickname(form.getNickname()) .role(Role.USER) // 신규 가입자는 항상 일반 사용자 .build(); // [4단계] DB에 저장 후 반환 return memberRepository.save(member); } // ── 로그인 ──────────────────────────────────────────── public Member login(LoginForm form) { // [1단계] 이메일로 회원 조회 → 없으면 예외 Member member = memberRepository.findByEmail(form.getEmail()) .orElseThrow(() -> new IllegalArgumentException("등록되지 않은 이메일입니다.")); // [2단계] BCrypt로 비밀번호 비교 if (!passwordEncoder.matches(form.getPassword(), member.getPassword())) { throw new IllegalArgumentException("비밀번호가 일치하지 않습니다."); } // [3단계] 로그인 성공 → 회원 정보 반환 return member; } // ── ID로 회원 조회 ────────────────────────────────────── public Member findById(Long id) { return memberRepository.findById(id) .orElseThrow(() -> new IllegalArgumentException("회원을 찾을 수 없습니다.")); } // ── 닉네임 변경 ────────────────────────────────────────── @Transactional public void updateNickname(Long id, String newNickname) { if (memberRepository.existsByNickname(newNickname)) { throw new IllegalArgumentException("이미 사용 중인 닉네임입니다."); } Member member = findById(id); member.updateNickname(newNickname); // JPA 더티 체킹 → 자동 UPDATE } // ── 비밀번호 변경 ────────────────────────────────────── @Transactional public void updatePassword(Long id, String encodedPassword) { Member member = findById(id); member.updatePassword(encodedPassword); // JPA 더티 체킹 → 자동 UPDATE } }
BCrypt 비밀번호 암호화란?
비밀번호를 되돌릴 수 없는 "해시(hash)"로 변환하는 알고리즘입니다.

"1234" → "$2a$10$N.zmdr9k7uOCQb376NoUnuTJ8iAt6Z5EHsM8lE9lBOsl4in9GGvri"

같은 "1234"를 두 번 암호화해도 매번 다른 결과가 나옵니다 (솔트salt 때문).
하지만 matches() 메서드로 원본과 해시가 일치하는지는 확인할 수 있습니다.

비유: "파쇄기" — 파쇄된 결과물(해시)로는 원본을 복원할 수 없지만, 같은 문서를 파쇄기에 넣으면 일치 여부는 확인 가능합니다.
@Transactional 정리

클래스 레벨: @Transactional(readOnly = true) — 기본적으로 모든 메서드 읽기 전용
메서드 레벨: @Transactional — 이 메서드만 쓰기 가능으로 전환

readOnly = true의 장점: DB가 불필요한 잠금(Lock)을 걸지 않아 성능이 향상됩니다.
쓰기 트랜잭션의 장점: 작업 도중 에러 발생 시 모든 변경사항이 자동으로 되돌려집니다(rollback).

package com.example.mymatzip.service; import com.example.mymatzip.dto.PageResponse; import com.example.mymatzip.dto.RestaurantForm; import com.example.mymatzip.dto.RestaurantResponse; import com.example.mymatzip.entity.Category; import lombok.RequiredArgsConstructor; import org.springframework.stereotype.Service; import org.springframework.transaction.annotation.Transactional; import org.springframework.data.domain.Page; import org.springframework.data.domain.Pageable; import com.example.mymatzip.util.HtmlSanitizer; import java.util.List; @Service @RequiredArgsConstructor @Transactional(readOnly = true) public class RestaurantService { private final RestaurantRepository restaurantRepository; } } // ── private: Entity → Response DTO 변환 ────────────────── private RestaurantResponse toResponse(Restaurant restaurant) { Double avgRating = reviewRepository.averageRatingByRestaurantId(restaurant.getId()); CRUD 패턴 정리

Create(생성): save() — Restaurant.builder()...build() → repository.save()
Read(조회): findAll(), findById(), findByCategory(), search()
Update(수정): update() — 권한 확인 → entity.update() → JPA 자동 UPDATE
Delete(삭제): delete() — 권한 확인 → repository.delete()

JPA 변경 감지(Dirty Checking): @Transactional 안에서 엔티티의 값을 변경하면, 트랜잭션 종료 시 자동으로 UPDATE 쿼리가 실행됩니다. 별도로 save()를 호출하지 않아도 됩니다!
.stream().map().toList() 패턴
Entity 목록을 Response DTO 목록으로 변환하는 패턴입니다:

.stream() — 리스트를 스트림(흐름)으로 변환
.map(this::toResponse) — 각 항목을 DTO로 변환
.toList() — 다시 리스트로 변환

비유: 컨베이어 벨트에 음식(Entity)을 올려놓고, 하나씩 접시(DTO)에 옮겨 담아 내보내는 것

package com.example.mymatzip.service; import com.example.mymatzip.dto.ReplyForm; import com.example.mymatzip.dto.ReplyResponse; import com.example.mymatzip.entity.Member; import com.example.mymatzip.entity.Reply; import com.example.mymatzip.entity.Review; import com.example.mymatzip.repository.ReplyRepository; import com.example.mymatzip.repository.ReviewRepository; import com.example.mymatzip.util.HtmlSanitizer; import lombok.RequiredArgsConstructor; import org.springframework.stereotype.Service; import org.springframework.transaction.annotation.Transactional; import java.util.List; @Service @RequiredArgsConstructor @Transactional(readOnly = true) public class ReplyService { private final ReplyRepository replyRepository; private final ReviewRepository reviewRepository; // 특정 리뷰의 대댓글 목록 조회 public List<ReplyResponse> findByReviewId(Long reviewId) { return replyRepository.findByReviewIdOrderByCreatedAtAsc(reviewId).stream() .map(ReplyResponse::from).toList(); } // 대댓글 작성 @Transactional public ReplyResponse save(ReplyForm form, Member loginMember) { Review review = reviewRepository.findById(form.getReviewId()) .orElseThrow(() -> new IllegalArgumentException("리뷰를 찾을 수 없습니다.")); Reply reply = Reply.builder() .content(HtmlSanitizer.sanitize(form.getContent())) .review(review) .member(loginMember) .build(); return ReplyResponse.from(replyRepository.save(reply)); } // 대댓글 삭제 @Transactional public void delete(Long id, Member loginMember) { Reply reply = replyRepository.findById(id) .orElseThrow(() -> new IllegalArgumentException("대댓글을 찾을 수 없습니다.")); if (!reply.getMember().getId().equals(loginMember.getId())) { throw new IllegalArgumentException("삭제 권한이 없습니다."); } replyRepository.delete(reply); } }

package com.example.mymatzip.service; import org.springframework.stereotype.Service; import org.springframework.web.multipart.MultipartFile; import java.io.IOException; import java.nio.file.Files; import java.nio.file.Path; import java.nio.file.Paths; import java.util.Set; import java.util.UUID; @Service public class FileService { private static final String UPLOAD_DIR = "uploads"; private static final Set<String> ALLOWED_EXTENSIONS = Set.of("jpg", "jpeg", "png", "gif", "webp"); public String upload(MultipartFile file) throws IOException { if (file.isEmpty()) { throw new IllegalArgumentException("파일이 비어있습니다."); } String originalFilename = file.getOriginalFilename(); String extension = getExtension(originalFilename).toLowerCase(); if (!ALLOWED_EXTENSIONS.contains(extension)) { throw new IllegalArgumentException( "허용되지 않는 파일 형식입니다. (jpg, png, gif, webp만 가능)"); } // uploads 디렉토리 생성 Path uploadPath = Paths.get(UPLOAD_DIR); if (!Files.exists(uploadPath)) { Files.createDirectories(uploadPath); } // UUID로 파일명 변환 (중복 방지) String savedFilename = UUID.randomUUID() + "." + extension; Path filePath = uploadPath.resolve(savedFilename); // 파일 저장 file.transferTo(filePath.toFile()); return "/uploads/" + savedFilename; } private String getExtension(String filename) { if (filename == null || !filename.contains(".")) { throw new IllegalArgumentException("파일 확장자를 확인할 수 없습니다."); } return filename.substring(filename.lastIndexOf(".") + 1); } }
FileService의 보안 처리
1. 확장자 검증: jpg, png, gif, webp만 허용 (악성 파일 업로드 방지)
2. UUID 파일명: 원본 파일명 대신 UUID로 변경 (파일명 충돌 방지 + 보안)
3. 디렉토리 자동 생성: uploads 폴더가 없으면 자동으로 생성
