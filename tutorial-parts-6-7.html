Part 6: Spring Security — 보안 시스템 구축

이제 애플리케이션의 보안(Security)을 담당하는 클래스들을 만들어 보겠습니다. Spring Security는 로그인, 권한 검사, 비밀번호 암호화 등 보안과 관련된 모든 것을 처리하는 프레임워크입니다.

비유: 보안 회사 고용하기
이전에는 LoginInterceptor(경비원 1명)가 로그인 여부만 확인했습니다. Spring Security는 "보안 회사 전체"를 고용한 것과 같습니다. 비밀번호 암호화, CSRF 공격 방어, 역할별 접근 제어, JWT 토큰 인증, 세션 관리 등 모든 보안 기능을 제공합니다.

Step 18: CustomUserDetails & CustomUserDetailsService

Spring Security가 우리 앱의 회원 정보를 이해할 수 있도록 "번역기"를 만들어야 합니다.

비유: 호텔 프론트 데스크 예약 확인 담당자
손님(사용자)이 체크인(로그인)할 때, 프론트 데스크 직원(CustomUserDetailsService)이 예약 장부(DB)에서 손님 정보를 찾아서 호텔 전산 시스템(Spring Security)이 이해할 수 있는 양식(CustomUserDetails)으로 변환합니다. 우리 앱의 Member 객체를 Spring Security의 UserDetails 인터페이스 형태로 감싸주는 것이 핵심입니다.
UserDetails 인터페이스란?
Spring Security가 사용자 정보를 다루기 위해 정의한 "표준 양식"입니다. 우리 앱은 Member라는 엔티티를 사용하지만, Spring Security는 UserDetails라는 인터페이스만 이해합니다. 따라서 Member를 UserDetails로 감싸주는 어댑터(adapter) 클래스가 필요합니다. 비유하면 외국 여권(Member)을 국내 신분증(UserDetails) 양식으로 변환하는 것입니다.

CustomUserDetails.javaJava
package com.example.mymatzip.config.security; import com.example.mymatzip.entity.Member; import lombok.Getter; import lombok.RequiredArgsConstructor; import org.springframework.security.core.GrantedAuthority; import org.springframework.security.core.authority.SimpleGrantedAuthority; import org.springframework.security.core.userdetails.UserDetails; import java.util.Collection; import java.util.List; import java.util.Map; import org.springframework.security.oauth2.core.user.OAuth2User; @Getter @RequiredArgsConstructor public class CustomUserDetails implements UserDetails, OAuth2User { // 우리 앱의 회원 엔티티 객체를 감싸서(wrap) Spring Security가 이해할 수 있는 형태로 제공 private final Member member; // 소셜 로그인(OAuth2) 시 제공되는 사용자 속성 정보 private Map<String, Object> attributes = Map.of(); // ── 이 사용자가 가진 "권한(역할) 목록"을 반환 ── // Spring Security는 이 메서드로 ADMIN인지 USER인지 확인합니다. // "ROLE_" 접두사는 Spring Security의 규칙입니다! @Override public Collection<? extends GrantedAuthority> getAuthorities() { return List.of(new SimpleGrantedAuthority("ROLE_" + member.getRole().name())); } // 암호화된 비밀번호를 반환 @Override public String getPassword() { return member.getPassword(); } // 로그인 ID(이메일)를 반환 @Override public String getUsername() { return member.getEmail(); } // ── 계정 상태 관련 메서드들 ── // 모두 true를 반환하면 "정상 계정"으로 인식합니다. @Override public boolean isAccountNonExpired() { return true; } @Override public boolean isAccountNonLocked() { return true; } @Override public boolean isCredentialsNonExpired() { return true; } @Override public boolean isEnabled() { return true; } // ── OAuth2User 인터페이스 구현 ── @Override public Map<String, Object> getAttributes() { return attributes; } @Override public String getName() { return member.getEmail(); } public void setAttributes(Map<String, Object> attributes) { this.attributes = attributes; } }
핵심 포인트 정리
  • getAuthorities(): 회원의 역할을 "ROLE_USER" 또는 "ROLE_ADMIN" 형태로 반환합니다. "ROLE_" 접두사는 Spring Security의 규칙이므로 반드시 붙여야 합니다.
  • getUsername(): Spring Security에서 "username"은 로그인 식별자입니다. 우리 앱에서는 이메일을 사용하므로 이메일을 반환합니다.
  • isAccountNonExpired() 등 4개 메서드: 모두 true를 반환하면 "정상 계정"입니다. 계정 잠금, 만료 기능이 필요하면 나중에 수정합니다.
  • OAuth2User도 함께 구현하여 소셜 로그인(Google, Kakao 등)에도 대응할 수 있습니다.

package com.example.mymatzip.config.security; import com.example.mymatzip.entity.Member; import com.example.mymatzip.repository.MemberRepository; import lombok.RequiredArgsConstructor; import org.springframework.security.core.userdetails.UserDetails; import org.springframework.security.core.userdetails.UserDetailsService; import org.springframework.security.core.userdetails.UsernameNotFoundException; import org.springframework.stereotype.Service; @Service @RequiredArgsConstructor public class CustomUserDetailsService implements UserDetailsService { // DB에서 회원 정보를 조회하기 위한 저장소 private final MemberRepository memberRepository; // ── 로그인 시 이메일(username)로 DB에서 회원 정보를 조회 ── // Spring Security가 자동으로 호출하는 메서드입니다. // UserDetailsService 인터페이스의 유일한 메서드이며, 반드시 구현해야 합니다. @Override public UserDetails loadUserByUsername(String email) throws UsernameNotFoundException { // [1단계] DB에서 이메일로 회원 조회 Member member = memberRepository.findByEmail(email) .orElseThrow(() -> new UsernameNotFoundException("등록되지 않은 이메일입니다: " + email)); // [2단계] Member를 CustomUserDetails로 감싸서 반환 return new CustomUserDetails(member); } }
동작 흐름 요약
  1. 사용자가 이메일/비밀번호로 로그인 요청
  2. Spring Security가 CustomUserDetailsService의 loadUserByUsername(email)을 호출
  3. DB에서 이메일로 회원을 조회
  4. 찾으면 CustomUserDetails로 감싸서 반환
  5. Spring Security가 비밀번호 비교 등 나머지 인증 처리를 진행

Step 19: JWT 토큰 (JwtTokenProvider)

JWT(JSON Web Token)는 사용자 인증 정보를 담은 "디지털 신분증"입니다. 서버가 발급하고, 클라이언트가 보관하며, API 요청 시 함께 보냅니다.

비유: 놀이공원 자유이용권 팔찌
  • 입구(로그인)에서 팔찌(JWT)를 발급받음
  • 놀이기구(API)를 탈 때마다 팔찌를 보여줌 (Authorization 헤더)
  • 팔찌에는 이름, 등급(VIP/일반) 등이 적혀있음 (Claims)
  • 유효기간이 지나면 더 이상 사용 불가 (만료)
JWT의 구조 (마침표로 3부분 구분)
xxxxx.yyyyy.zzzzz
  1. Header (헤더): 토큰 타입(JWT), 서명 알고리즘(HS256)
  2. Payload (내용): 사용자 정보(id, email, role), 만료 시간
  3. Signature (서명): 위변조 방지용 서명 (비밀키로 암호화)

세션(Session)과의 차이:
세션은 서버에 사용자 정보를 저장하여 서버 메모리를 사용하고 서버 확장이 어렵습니다. JWT는 클라이언트에 토큰을 저장하므로 서버 부담이 없고 확장이 용이합니다. 이 앱에서는 JSP 뷰에는 세션 기반, REST API에는 JWT 기반 인증을 사용합니다.

package com.example.mymatzip.config.security; import com.example.mymatzip.entity.Member; import io.jsonwebtoken.Claims; import io.jsonwebtoken.JwtException; import io.jsonwebtoken.Jwts; import io.jsonwebtoken.security.Keys; import org.springframework.beans.factory.annotation.Value; import org.springframework.stereotype.Component; import java.util.Date; import javax.crypto.SecretKey; @Component public class JwtTokenProvider { // JWT 서명에 사용할 비밀키 (application.properties에서 가져옴) // 이 키를 알아야 토큰을 생성/검증할 수 있으므로 절대 외부에 노출하면 안 됩니다! private final SecretKey secretKey; // JWT 토큰의 유효 기간 (밀리초 단위) // 86400000ms = 24시간 = 1일 private final long expiration; // ── 생성자: @Value로 application.properties의 값을 주입 ── public JwtTokenProvider(@Value("${jwt.secret}") String secret, @Value("${jwt.expiration}") long expiration) { this.secretKey = Keys.hmacShaKeyFor(secret.getBytes()); this.expiration = expiration; } // ── 회원 정보를 담은 JWT 토큰을 생성 ── public String generateToken(Member member) { Date now = new Date(); Date expiryDate = new Date(now.getTime() + expiration); return Jwts.builder() // subject: 토큰의 주체(주인) — 회원 ID .subject(String.valueOf(member.getId())) // claim: 추가 정보 — 이메일과 역할 .claim("email", member.getEmail()) .claim("role", member.getRole().name()) // 발급 시간 & 만료 시간 .issuedAt(now) .expiration(expiryDate) // 비밀키로 서명 (위변조 방지) .signWith(secretKey) .compact(); } // ── JWT 토큰이 유효한지 검증 ── public boolean validateToken(String token) { try { Jwts.parser() .verifyWith(secretKey) .build() .parseSignedClaims(token); return true; } catch (JwtException | IllegalArgumentException e) { return false; } } // ── JWT 토큰에서 회원 ID를 추출 ── public Long getMemberIdFromToken(String token) { Claims claims = Jwts.parser() .verifyWith(secretKey) .build() .parseSignedClaims(token) .getPayload(); return Long.parseLong(claims.getSubject()); } }
JwtTokenProvider의 3가지 핵심 메서드
  • generateToken(Member): 로그인 성공 시 JWT 토큰을 발급합니다. 회원 ID, 이메일, 역할, 만료 시간을 토큰에 담습니다.
  • validateToken(String): 토큰이 유효한지 검증합니다. 서명 불일치, 만료, 형식 오류 등이 있으면 false를 반환합니다.
  • getMemberIdFromToken(String): 토큰에서 회원 ID를 추출합니다. 인증 필터에서 사용합니다.

Step 20: JWT 인증 필터 (JwtAuthenticationFilter)

모든 API 요청이 Controller에 도달하기 전에 JWT 토큰을 검증하는 "API 전용 보안 검문소"입니다.

비유: 공항 보안 검색대
모든 API 요청은 Controller에 도달하기 전에 이 필터를 통과해야 합니다.
  • 탑승권(JWT 토큰)이 있으면 → 검증 후 통과
  • 탑승권이 없으면 → 통과 (허용된 경로라면 다음 필터에서 처리)
  • 가짜/만료된 탑승권이면 → 통과하되 인증은 설정하지 않음
OncePerRequestFilter란?
"한 번의 요청에 한 번만 실행되는 필터"입니다. 일반 Filter는 포워드(forward) 등으로 여러 번 실행될 수 있지만, OncePerRequestFilter는 같은 요청에 대해 딱 한 번만 실행됩니다. JWT 토큰 검증은 요청당 한 번만 하면 되므로 이 클래스를 상속합니다.
@Lazy 어노테이션이 왜 필요한가?
JwtAuthenticationFilter → MemberService → PasswordEncoder → SecurityConfig → JwtAuthenticationFilter 순서로 순환 참조가 발생합니다. @Lazy를 붙이면 프록시 객체가 먼저 주입되고, 실제 호출 시점에만 진짜 빈을 가져옵니다. 비유하면 "대리인을 먼저 보내놓고, 실제 일이 생기면 본인이 나서는 것"입니다.

JwtAuthenticationFilter.javaJava
package com.example.mymatzip.config.security; import jakarta.servlet.FilterChain; import jakarta.servlet.ServletException; import jakarta.servlet.http.HttpServletRequest; import jakarta.servlet.http.HttpServletResponse; import lombok.RequiredArgsConstructor; import com.example.mymatzip.entity.Member; import com.example.mymatzip.service.MemberService; import org.springframework.security.authentication.UsernamePasswordAuthenticationToken; import org.springframework.security.core.context.SecurityContextHolder; import org.springframework.security.core.userdetails.UserDetails; import org.springframework.security.web.authentication.WebAuthenticationDetailsSource; import org.springframework.stereotype.Component; import org.springframework.web.filter.OncePerRequestFilter; import java.io.IOException; @Component public class JwtAuthenticationFilter extends OncePerRequestFilter { private final JwtTokenProvider jwtTokenProvider; private final CustomUserDetailsService customUserDetailsService; // @Lazy: 순환 참조 방지 — 실제 사용 시점까지 빈 생성을 지연 private final MemberService memberService; // 생성자 — MemberService에 @Lazy 적용하기 위해 직접 작성 public JwtAuthenticationFilter(JwtTokenProvider jwtTokenProvider, CustomUserDetailsService customUserDetailsService, @org.springframework.context.annotation.Lazy MemberService memberService) { this.jwtTokenProvider = jwtTokenProvider; this.customUserDetailsService = customUserDetailsService; this.memberService = memberService; } // ── 요청마다 한 번 실행되는 핵심 메서드 ── @Override protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) throws ServletException, IOException { // [1단계] /api/** 경로가 아니면 JWT 검증을 건너뜀 String requestURI = request.getRequestURI(); if (!requestURI.startsWith("/api/")) { filterChain.doFilter(request, response); return; } // [2단계] Authorization 헤더에서 JWT 토큰 추출 String token = extractTokenFromRequest(request); // [3단계] 토큰이 있고 유효한 경우 → 인증 정보 설정 if (token != null && jwtTokenProvider.validateToken(token)) { try { Long memberId = jwtTokenProvider.getMemberIdFromToken(token); Member member = memberService.findById(memberId); UserDetails userDetails = new CustomUserDetails(member); // Spring Security의 인증 토큰 생성 UsernamePasswordAuthenticationToken authentication = new UsernamePasswordAuthenticationToken( userDetails, null, userDetails.getAuthorities()); authentication.setDetails( new WebAuthenticationDetailsSource().buildDetails(request)); // SecurityContextHolder에 인증 정보 저장 SecurityContextHolder.getContext().setAuthentication(authentication); } catch (Exception e) { // 회원 조회 실패 시 인증 설정 없이 통과 } } // [4단계] 다음 필터로 요청 전달 filterChain.doFilter(request, response); } // ── Authorization 헤더에서 Bearer 토큰 추출 ── private String extractTokenFromRequest(HttpServletRequest request) { String bearerToken = request.getHeader("Authorization"); if (bearerToken != null && bearerToken.startsWith("Bearer ")) { return bearerToken.substring(7); } return null; } }
동작 흐름 요약
  1. HTTP 요청이 들어옴
  2. URL이 /api/**가 아니면 → 바로 통과 (세션 기반 인증 사용)
  3. URL이 /api/**이면 → Authorization 헤더에서 Bearer 토큰 추출
  4. 토큰이 유효하면 → SecurityContextHolder에 인증 정보 설정
  5. 토큰이 없거나 유효하지 않으면 → 인증 정보 설정 없이 통과 (이후 SecurityConfig에서 허용/거부 결정)

Step 21: @LoginMember 어노테이션 & ArgumentResolver

컨트롤러 메서드에서 현재 로그인한 회원 정보를 간편하게 받을 수 있도록 커스텀 어노테이션과 인자 해석기(ArgumentResolver)를 만듭니다.

비유: 회원증을 자동으로 확인해서 건네주는 도우미
컨트롤러 메서드에 @LoginMember Member loginMember라고 적어두면, Spring이 자동으로 현재 로그인한 회원 정보를 찾아서 넣어줍니다. 식당에서 "단골손님" 스티커(@LoginMember)가 붙은 자리에 직원이 자동으로 그 손님의 정보(Member)를 가져다 놓는 것과 같습니다.
사용 전 vs 사용 후 비교
기존 방식 (세션에서 직접 꺼내기):
public ResponseEntity<?> create(..., HttpSession session) { Member loginMember = (Member) session.getAttribute("loginMember"); }

@LoginMember 사용 후 (깔끔하고 안전):
public ResponseEntity<?> create(..., @LoginMember Member loginMember) { // loginMember가 자동으로 주입됨! }

package com.example.mymatzip.config.security; import java.lang.annotation.ElementType; import java.lang.annotation.Retention; import java.lang.annotation.RetentionPolicy; import java.lang.annotation.Target; // 이 어노테이션은 "매개변수(파라미터)"에만 붙일 수 있습니다. @Target(ElementType.PARAMETER) // 프로그램 실행 중(런타임)에도 이 어노테이션 정보를 유지합니다. // RUNTIME이어야 Spring이 실행 중에 이 어노테이션을 읽을 수 있습니다. @Retention(RetentionPolicy.RUNTIME) public @interface LoginMember { // 어노테이션 내부에 별도의 속성은 없습니다. // 단순히 "이 매개변수에 로그인 회원 정보를 넣어달라"는 표시 역할만 합니다. }
커스텀 어노테이션 만드는 법
  • @interface: 어노테이션을 정의할 때 사용하는 키워드입니다 (class 대신).
  • @Target(ElementType.PARAMETER): 이 어노테이션을 매개변수에만 붙일 수 있도록 제한합니다.
  • @Retention(RetentionPolicy.RUNTIME): 실행 중에도 어노테이션 정보를 유지합니다. Spring이 런타임에 이 어노테이션을 읽어야 하므로 필수입니다.

package com.example.mymatzip.config.security; import com.example.mymatzip.entity.Member; import org.springframework.security.core.Authentication; import org.springframework.security.core.context.SecurityContextHolder; import org.springframework.core.MethodParameter; import org.springframework.stereotype.Component; import org.springframework.web.bind.support.WebDataBinderFactory; import org.springframework.web.context.request.NativeWebRequest; import org.springframework.web.method.support.HandlerMethodArgumentResolver; import org.springframework.web.method.support.ModelAndViewContainer; @Component public class LoginMemberArgumentResolver implements HandlerMethodArgumentResolver { // ── "이 매개변수를 내가 처리할 수 있는가?" 판단 ── // 조건: @LoginMember 어노테이션이 붙어있고 + 타입이 Member인 경우 @Override public boolean supportsParameter(MethodParameter parameter) { boolean hasAnnotation = parameter.hasParameterAnnotation(LoginMember.class); boolean isMemberType = Member.class.isAssignableFrom(parameter.getParameterType()); return hasAnnotation && isMemberType; } // ── 실제로 매개변수에 넣어줄 값(Member 객체)을 가져옴 ── @Override public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer, NativeWebRequest webRequest, WebDataBinderFactory binderFactory) { // [1단계] SecurityContextHolder에서 현재 인증 정보 가져오기 Authentication authentication = SecurityContextHolder.getContext().getAuthentication(); // [2단계] 인증되지 않은 경우 null 반환 if (authentication == null || !authentication.isAuthenticated()) { return null; } // [3단계] principal(주체) 가져오기 Object principal = authentication.getPrincipal(); // [4단계] CustomUserDetails인 경우에만 Member 추출 if (principal instanceof CustomUserDetails) { return ((CustomUserDetails) principal).getMember(); } return null; } }
HandlerMethodArgumentResolver 인터페이스
Controller 메서드의 매개변수를 해석하는 인터페이스입니다. 2개의 메서드를 구현해야 합니다:
  • supportsParameter(): "이 매개변수를 내가 처리할 수 있는가?" — @LoginMember가 붙어있고 Member 타입이면 true
  • resolveArgument(): "실제로 넣어줄 값을 가져와라" — SecurityContextHolder에서 현재 인증 정보를 꺼내서 Member 객체를 반환
이 ArgumentResolver는 WebMvcConfig에서 등록해야 동작합니다 (Part 7에서 다룹니다).

Step 22: GlobalModelAdvice & SecurityConfig 완성

모든 JSP 페이지에서 로그인 회원 정보를 자동으로 사용할 수 있게 해주는 GlobalModelAdvice와, 보안의 모든 것을 총괄하는 SecurityConfig의 완성 버전을 작성합니다.

비유: 건물 보안 시스템 완성
GlobalModelAdvice는 백화점의 "안내 방송 시스템"입니다. 각 매장(Controller)에서 일일이 손님 정보를 알려주지 않아도, 안내 방송이 자동으로 모든 매장에 현재 손님 정보를 전달합니다.

SecurityConfig는 건물의 "보안 설계도"입니다. 어떤 출입구(URL)는 누구나 통과 가능하고, 어떤 출입구는 직원증(로그인)이 필요하고, 어떤 출입구는 관리자 카드키가 필요합니다.
생성할 파일: src/main/java/com/example/mymatzip/config/security/GlobalModelAdvice.java
GlobalModelAdvice.javaJava
package com.example.mymatzip.config.security; import com.example.mymatzip.entity.Member; import org.springframework.security.core.Authentication; import org.springframework.security.core.context.SecurityContextHolder; import org.springframework.web.bind.annotation.ControllerAdvice; import org.springframework.web.bind.annotation.ModelAttribute; @ControllerAdvice public class GlobalModelAdvice { // 이 메서드의 반환값을 "loginMember"라는 이름으로 Model에 자동 추가 // → JSP에서 ${loginMember.nickname} 등으로 접근 가능! @ModelAttribute("loginMember") public Member loginMember() { Authentication authentication = SecurityContextHolder.getContext().getAuthentication(); if (authentication != null && authentication.isAuthenticated() && authentication.getPrincipal() instanceof CustomUserDetails) { CustomUserDetails userDetails = (CustomUserDetails) authentication.getPrincipal(); return userDetails.getMember(); } // 로그인하지 않은 상태 → null 반환 return null; } }
@ControllerAdvice란?
모든 Controller에 공통으로 적용되는 "전역 조언자"입니다. 이 클래스에 정의된 @ModelAttribute 메서드는 모든 요청에서 자동으로 실행됩니다.

왜 필요한가?
Spring Security로 전환하면서 인증 정보가 SecurityContextHolder에 저장됩니다. 하지만 JSP에서는 SecurityContextHolder에 직접 접근하기 어려우므로, 이 클래스가 자동으로 Model에 loginMember를 추가해줍니다. 이제 모든 JSP에서 ${loginMember}로 회원 정보에 접근할 수 있습니다.

이제 Spring Security의 핵심인 SecurityConfig의 완전한 버전을 작성합니다. Step 4에서 만들었던 최소 버전을 이 완성 버전으로 교체합니다.

SecurityConfig 핵심 설정 해설
  • CSRF 방어: CookieCsrfTokenRepository를 사용하여 CSRF 토큰을 쿠키에 저장합니다. /api/** 경로는 JWT로 인증하므로 CSRF를 제외합니다.
  • URL 권한: permitAll()은 누구나 접근 가능, hasRole("ADMIN")은 관리자만, authenticated()는 로그인한 사용자만 접근 가능합니다.
  • DispatcherType 설정: Spring Security 6.x는 FORWARD 디스패치도 보안 검사를 합니다. JSP 포워딩 시 리다이렉트 루프를 방지하기 위해 FORWARD, INCLUDE, ERROR를 허용합니다.
  • 폼 로그인: loginProcessingUrl("/perform-login")은 사용되지 않는 별도 경로로, 실제 로그인은 /api/members/login REST API에서 처리합니다.
  • 세션 정책: IF_REQUIRED는 필요할 때만 세션을 생성합니다 (JSP 뷰는 세션 사용, API는 JWT 사용).
  • JWT 필터 배치: addFilterBefore로 JWT 필터를 기본 인증 필터 앞에 배치하여 API 요청 시 JWT를 먼저 검증합니다.
IntelliJ 팁: PasswordEncoder 빈이 어디에 등록되어 있는지 궁금하다면, 프로젝트에서 @Bean과 PasswordEncoder를 함께 검색해보세요. 보통 SecurityConfig나 별도의 설정 클래스에 BCryptPasswordEncoder를 @Bean으로 등록합니다.

23-1. DataInitializer — 데이터 초기화 도우미

서버 시작 시 data.sql로 생성된 회원들의 비밀번호를 BCrypt로 암호화하는 "초기화 도우미"입니다.

비유: 보안 업그레이드 담당자
새 건물(서버)이 완공되면, 입주자(회원)들의 임시 출입증(평문 비밀번호 '1234')을 보안 카드(BCrypt 해시)로 교체해주는 담당자입니다. data.sql에서 INSERT할 때 비밀번호를 평문으로 넣지만, Spring Security는 BCrypt로 암호화된 비밀번호를 기대합니다. 따라서 서버 시작 직후 이 클래스가 평문 비밀번호를 BCrypt 해시로 변환합니다.
CommandLineRunner 인터페이스란?
CommandLineRunner를 구현하면 Spring Boot가 완전히 시작된 후 run() 메서드가 자동으로 실행됩니다. 실행 순서: 테이블 생성 → data.sql INSERT → 이 클래스의 run() 실행. 서버 시작 시 한 번만 실행되는 초기화 작업에 적합합니다. 비유하면 가게 오픈 전 "준비 작업"을 자동으로 해주는 것입니다.
생성할 파일: src/main/java/com/example/mymatzip/config/DataInitializer.java
DataInitializer.javaJava
package com.example.mymatzip.config; import com.example.mymatzip.repository.MemberRepository; import lombok.RequiredArgsConstructor; import org.springframework.boot.CommandLineRunner; import org.springframework.security.crypto.password.PasswordEncoder; import org.springframework.stereotype.Component; import org.springframework.transaction.annotation.Transactional; @Component @RequiredArgsConstructor public class DataInitializer implements CommandLineRunner { private final MemberRepository memberRepository; private final PasswordEncoder passwordEncoder; // Spring Boot 시작 완료 후 자동 실행 // 평문 비밀번호를 BCrypt로 변환 @Override @Transactional public void run(String... args) { // data.sql로 생성된 모든 회원을 조회 memberRepository.findAll().forEach(member -> { // 이미 BCrypt 해시가 아닌 경우에만 암호화 (이중 암호화 방지) // BCrypt 해시는 "$2a$"로 시작합니다. if (!member.getPassword().startsWith("$2a$")) { member.encodePassword(passwordEncoder); // JPA 더티 체킹에 의해 @Transactional 안에서 자동 UPDATE } }); } }
BCrypt 이중 암호화 방지 로직
이미 BCrypt로 암호화된 비밀번호는 "$2a$"로 시작합니다. startsWith("$2a$")로 체크하여, 이미 암호화된 비밀번호는 건너뜁니다. 따라서 서버를 여러 번 재시작해도 이중 암호화되지 않습니다. 또한 @Transactional 안에서 엔티티의 필드를 변경하면 JPA의 "더티 체킹(dirty checking)"에 의해 별도로 save()를 호출하지 않아도 자동으로 DB에 반영됩니다.

23-3. 보조 인프라 클래스들

아래 두 파일은 참고용으로 접어두었습니다. GlobalExceptionHandler는 REST API의 에러를 깔끔하게 처리하고, LoginInterceptor는 Spring Security 도입 이전에 사용하던 세션 기반 로그인 검사 방식입니다.

GlobalExceptionHandler.java — 전역 예외 처리기 (클릭하여 펼치기)
비유: 고객 불만 처리 센터
각 부서(Controller)에서 직접 처리하지 못한 문제(예외)가 생기면, 이 센터가 대신 깔끔하게 응답을 만들어서 고객(브라우저)에게 전달합니다.
@RestControllerAdvice & @ExceptionHandler
  • @RestControllerAdvice: 모든 @RestController에 적용되는 "전역 조언자"입니다. @ControllerAdvice + @ResponseBody를 합친 것입니다.
  • @ExceptionHandler(예외클래스.class): 특정 예외가 발생했을 때 이 메서드가 처리하겠다고 표시합니다. 비유하면 "이 유형의 불만은 제가 맡겠습니다"라고 담당자를 지정하는 것입니다.
생성할 파일: src/main/java/com/example/mymatzip/config/GlobalExceptionHandler.java
GlobalExceptionHandler.javaJava
package com.example.mymatzip.config; import org.springframework.http.ResponseEntity; import org.springframework.web.bind.MethodArgumentNotValidException; import org.springframework.web.bind.annotation.ExceptionHandler; import org.springframework.web.bind.annotation.RestControllerAdvice; import java.util.Map; @RestControllerAdvice public class GlobalExceptionHandler { // ── @Valid 유효성 검증 실패 시 처리 ── // 예: 이메일 형식이 틀렸거나, 필수 값이 비어있을 때 @ExceptionHandler(MethodArgumentNotValidException.class) public ResponseEntity<Map<String, String>> handleValidation(MethodArgumentNotValidException e) { String message = e.getBindingResult().getFieldErrors().stream() .map(error -> error.getField() + ": " + error.getDefaultMessage()) .findFirst() .orElse("입력값이 올바르지 않습니다."); return ResponseEntity.badRequest().body(Map.of("error", message)); } // ── 잘못된 인자(값) 예외 처리 ── // 예: 이미 사용 중인 이메일, 존재하지 않는 ID 등 @ExceptionHandler(IllegalArgumentException.class) public ResponseEntity<Map<String, String>> handleIllegalArgument(IllegalArgumentException e) { return ResponseEntity.badRequest().body(Map.of("error", e.getMessage())); } }
LoginInterceptor.java — 세션 기반 로그인 인터셉터 (클릭하여 펼치기)
비유: 놀이공원 입구의 티켓 검사원
이 클래스는 Spring Security 도입 이전에 사용하던 로그인 검사 방식입니다. 세션에 저장된 로그인 정보를 확인하여, 로그인하지 않은 사용자를 로그인 페이지로 안내합니다. 현재는 Spring Security의 필터 체인이 이 역할을 대체하지만, 학습 목적으로 포함합니다.
HandlerInterceptor 인터페이스
스프링이 제공하는 인터셉터 인터페이스입니다. preHandle() 메서드를 구현하면 Controller 실행 전에 로직을 실행할 수 있습니다. true를 반환하면 요청이 Controller로 전달되고, false를 반환하면 요청이 중단됩니다.
생성할 파일: src/main/java/com/example/mymatzip/config/LoginInterceptor.java
LoginInterceptor.javaJava
package com.example.mymatzip.config; import jakarta.servlet.http.HttpServletRequest; import jakarta.servlet.http.HttpServletResponse; import jakarta.servlet.http.HttpSession; import org.springframework.stereotype.Component; import org.springframework.web.servlet.HandlerInterceptor; @Component public class LoginInterceptor implements HandlerInterceptor { // ── 요청이 Controller에 도달하기 "전"에 실행 ── // 반환값 true → 통과, false → 요청 중단 @Override public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception { // [1단계] 세션 가져오기 (없으면 null 반환, 새로 만들지 않음) HttpSession session = request.getSession(false); // [2단계] 세션이 없거나 로그인 정보가 없으면 if (session == null || session.getAttribute("loginMember") == null) { // 로그인 페이지로 리다이렉트 response.sendRedirect("/members/login"); return false; } // [3단계] 로그인 확인 완료 → Controller로 전달 return true; } }
체크포인트: Part 7 완료 확인
  • 서버를 재시작(Shift+F10)하세요.
  • 콘솔 로그에서 DataInitializer가 정상 실행되었는지 확인하세요. 에러 없이 서버가 뜨면 비밀번호 암호화가 완료된 것입니다.
  • H2 콘솔에서 SELECT * FROM MEMBER를 실행하여 비밀번호가 $2a$10$... 형태의 BCrypt 해시로 저장되었는지 확인하세요.
  • CSS, JS 파일이 정상적으로 로드되는지 브라우저 개발자 도구(F12)의 Network 탭에서 확인하세요.
Part 6-7 완료! 전체 보안 시스템 요약
  1. CustomUserDetails / CustomUserDetailsService: 우리 앱의 Member를 Spring Security가 이해할 수 있는 형태로 변환
  2. JwtTokenProvider: JWT 토큰의 생성, 검증, 파싱 담당
  3. JwtAuthenticationFilter: API 요청 시 JWT 토큰을 자동 검증하는 필터
  4. @LoginMember + ArgumentResolver: 컨트롤러에서 로그인 회원 정보를 간편하게 받는 기능
  5. GlobalModelAdvice: 모든 JSP에서 ${loginMember}로 회원 정보 접근 가능
  6. SecurityConfig: URL별 접근 권한, CSRF 방어, 폼 로그인, JWT 필터 등 보안 총괄 설정
  7. DataInitializer: 서버 시작 시 평문 비밀번호를 BCrypt로 자동 암호화
  8. WebMvcConfig: 정적 리소스 매핑 + ArgumentResolver 등록
